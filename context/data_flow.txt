# DATA FLOW

## Overview

This document traces how data moves through the Smarty system, from user input to AI response and persistence.

---

## DATA FLOW 1: CHAT MESSAGE PROCESSING

### Flow: User Input → AI Response → Display

```
┌──────────────┐     ┌──────────────┐     ┌──────────────┐
│   Android    │     │    Server    │     │   External   │
│    Client    │     │   (Ktor)     │     │   Services   │
└──────┬───────┘     └──────┬───────┘     └──────┬───────┘
       │                    │                    │
       │ 1. User types      │                    │
       │    message         │                    │
       │───────────────────>│                    │
       │                    │                    │
       │                    │ 2. Parse request   │
       │                    │    Validate auth   │
       │                    │                    │
       │                    │ 3. Load history    │
       │                    │    from PostgreSQL │
       │                    │<───────────────────│
       │                    │                    │
       │                    │ 4. RAG: Search     │
       │                    │    vector store    │
       │                    │───────────────────>│
       │                    │<───────────────────│
       │                    │                    │
       │                    │ 5. Call LLM        │
       │                    │    (Gemini)        │
       │                    │───────────────────>│
       │                    │                    │
       │ 6. SSE Stream:     │                    │
       │    Processing      │<───────────────────│
       │    events          │ 7. Stream tokens   │
       │<───────────────────│                    │
       │                    │                    │
       │                    │ 8. Tool call       │
       │                    │    detected        │
       │                    │───────────────────>│
       │                    │    (Tavily search) │
       │                    │<───────────────────│
       │                    │                    │
       │ 9. SSE Stream:     │                    │
       │    ToolCall event  │                    │
       │<───────────────────│                    │
       │                    │                    │
       │                    │ 10. Continue LLM   │
       │                    │     streaming      │
       │                    │<───────────────────│
       │                    │                    │
       │ 11. SSE Stream:    │                    │
       │     Result events  │                    │
       │<───────────────────│                    │
       │                    │                    │
       │                    │ 12. Save message   │
       │                    │     to PostgreSQL  │
       │                    │───────────────────>│
       │                    │                    │
       │ 13. Update UI      │                    │
       │     Display final  │                    │
       │     response       │                    │
       │                    │                    │
```

### Data Transformations

**Step 1: User Input**
```kotlin
// Android: ViewModel collects input
data class ChatMessage(
    val content: String,
    val attachments: List<Attachment>
)
```

**Step 2: Request Serialization**
```kotlin
// Ktor Client → Server
GET /chat/stream?query=...&sessionId=...
Authorization: Bearer <firebase_token>
```

**Step 3: History Retrieval**
```kotlin
// Server: ChatRepository
val history = chatRepository.getHistory(userId, sessionId)
// Returns: List<LlmMessage>
```

**Step 4: RAG Context**
```kotlin
// Server: PostgresVectorStore
val context = vectorStore.search(userId, query, limit = 5)
// Returns: List<VectorSearchResult>
```

**Step 5-7: LLM Streaming**
```kotlin
// Server: GeminiProvider
val chunks: Flow<LlmChunk> = llmProvider.stream(messages)
// Emits: LlmChunk(content, reasoning, usage)
```

**Step 6, 9, 11: SSE Events**
```kotlin
// Server → Client
event: processing
data: {"eventId":"uuid","timestamp":123,"content":"Thinking..."}

event: tool_call
data: {"toolName":"web_search","status":"started"}

event: result
data: {"content":"Response text","isFinal":true}
```

**Step 12: Persistence**
```kotlin
// Server: ChatRepository
chatRepository.saveMessage(
    userId = userId,
    sessionId = sessionId,
    role = "assistant",
    content = response,
    thinking = thinkingTrace,
    toolCalls = citationsJson
)
```

```
┌──────────────┐     ┌──────────────┐     ┌──────────────┐

       │    request         │                    │
       │───────────────────>│                    │
       │                    │                    │
       │                    │ 2. Create research │
       │                    │    session state   │
       │                    │                    │
       │                    │ 3. Generate        │
       │                    │    clarifying Qs   │
       │                    │                    │
       │ 4. Return Qs       │                    │
       │<───────────────────│                    │
       │                    │                    │
       │ 5. Submit answers  │                    │
       │───────────────────>│                    │
       │                    │                    │
       │                    │ 6. Create research │
       │                    │    plan (LLM)      │
       │                    │───────────────────>│
       │                    │<───────────────────│
       │                    │                    │
       │                    │ 7. Execute parallel│
       │                    │    searches (10x)  │
       │                    │───────────────────>│
       │                    │<───────────────────│
       │                    │                    │
       │ 8. SSE: Search     │                    │
       │    progress        │                    │

       │                    │                    │
       │                    │ 9. Scrape top URLs │
       │                    │───────────────────>│

       │                    │                    │

       │                    │     to file/DB     │
       │                    │                    │
       │                    │ 11. Analyze &      │
       │                    │     gap-fill       │
       │                    │───────────────────>│
       │                    │<───────────────────│
       │                    │                    │
       │                    │ 12. Synthesize     │
       │                    │     report (LLM)   │

       │                    │<───────────────────│
       │                    │                    │
```

```
       │    action needed  │
```

## DATA FLOW 5: SYNC PROTOCOL

### Flow: Local Changes → Server Sync → Conflict Resolution

```
┌──────────────┐     ┌──────────────┐
│   Android    │     │    Server    │
│   (Room)     │     │  (PostgreSQL)│
└──────┬───────┘     └──────┬───────┘
       │                    │
       │ 1. User creates    │
       │    note locally    │
       │                    │
       │ 2. Save to Room    │
       │    + sync_queue    │
       │                    │
       │ 3. WorkManager     │
       │    triggers sync   │
       │                    │
       │ 4. POST /sync/push │
       │    (pending ops)   │
       │───────────────────>│
       │                    │
       │                    │ 5. Apply changes
       │                    │    to PostgreSQL
       │                    │
       │                    │ 6. Update sync_state
       │                    │
       │ 7. POST /sync/pull │
       │    (last_sync_at)  │
       │───────────────────>│
       │                    │
       │                    │ 8. Query changes
       │                    │    since timestamp
       │                    │
       │ 9. Return delta    │
       │<───────────────────│
       │                    │
       │ 10. Apply to Room  │
       │     + update sync  │
       │     state          │
       │                    │
```

### Sync Queue Schema

```kotlin

```

### Sync State

```
┌──────────────┐     ┌──────────────┐     ┌──────────────┐

└──────┬───────┘     └──────┬───────┘     └──────┬───────┘
       │                    │                    │
       │ 1. Daily trigger   │                    │
       │    (7:00 AM)       │                    │
       │───────────────────>│                    │
       │                    │                    │
       │                    │ 2. Fetch user's    │
       │                    │    activities      │
       │                    │                    │
       │                    │ 3. Query: notes,   │
       │                    │    chats, tasks    │
       │                    │    (yesterday)     │
       │                    │                    │
       │                    │ 4. LLM synthesis   │
       │                    │───────────────────>│
       │                    │<───────────────────│
       │                    │                    │
       │                    │ 5. Create digest   │
       │                    │    document        │
       │                    │                    │
       │                    │ 6. Create calendar │
       │                    │    event           │
       │                    │                    │
       │                    │ 7. Send FCM        │
```

|-----------|----------------|---------------------|----------|
| Notes | ✓ | ✓ | - |
| Chat Sessions | ✓ (cache) | ✓ (primary) | - |
| Chat Messages | ✓ (cache) | ✓ (primary) | - |
| Calendar Events | ✓ | ✓ | Google Calendar (optional) |
| Timers | ✓ | ✓ | - |
| User Preferences | ✓ (DataStore) | ✓ | - |
