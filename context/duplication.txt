# DUPLICATION ANALYSIS

## Overview

This document identifies duplicate logic, similar patterns, and opportunities for code consolidation.

---

## DUPLICATE PATTERNS

### 1. Repository Pattern Duplication

**Files:**
- `server/src/main/kotlin/com/example/smarty/server/data/NoteRepository.kt`
- `server/src/main/kotlin/com/example/smarty/server/data/ChatRepository.kt`
- `server/src/main/kotlin/com/example/smarty/server/data/CalendarRepository.kt`
- `server/src/main/kotlin/com/example/smarty/server/data/TimerRepository.kt`

**Pattern:** Each repository implements similar CRUD operations

**Example:**
```kotlin
// NoteRepository
class NoteRepository(private val dataSource: DataSource, ...) {
    suspend fun getAll(userId: String, ...): List<Note>
    suspend fun getById(userId: String, id: String): Note?
    suspend fun create(note: Note): Note
    suspend fun update(note: Note): Note
    suspend fun delete(userId: String, id: String)
}

// ChatRepository - Same pattern
class ChatRepository(private val dataSource: DataSource, ...) {
    suspend fun getAll(userId: String, ...): List<ChatSession>
    suspend fun getById(userId: String, id: String): ChatSession?
    suspend fun create(session: ChatSession): ChatSession
    suspend fun update(session: ChatSession): ChatSession
    suspend fun delete(userId: String, id: String)
}
```

**Impact:** Code duplication, maintenance overhead

**Recommendation:** Create generic `BaseRepository<T>` with common operations

**Current State:** `BaseRepository.kt` exists but may not be fully utilized

### 2. Event Emission Pattern

**Files:**
- `server/src/main/kotlin/com/example/smarty/server/routes/ChatRoutes.kt`
- `server/src/main/kotlin/com/example/smarty/server/routes/ResearchRoutes.kt`

**Pattern:** SSE event emission logic duplicated

**Example:**
```kotlin
// ChatRoutes.kt
eventEmitter = { event ->
    try {
        val eventType = when(event) {
            is AgentEvent.Processing -> "processing"
            is AgentEvent.ToolCall -> "tool_call"
            is AgentEvent.Result -> "result"
            is AgentEvent.Error -> "error"
            ...
        }
        send(ServerSentEvent(data = json.encodeToString(event), event = eventType))
    } catch (e: Exception) {
        logger.warn("Failed to send SSE event: ${e.message}")
    }
}

// Similar pattern in ResearchRoutes.kt
```

**Recommendation:** Extract to `SseEventEmitter` utility class

### 3. Authentication Pattern

**Files:** Multiple route files

**Pattern:** Firebase user extraction duplicated

**Example:**
```kotlin
// ChatRoutes.kt
val user = call.firebaseUser()
if (user == null) {
    call.respond(HttpStatusCode.Unauthorized, mapOf("error" to "Authentication required"))
    return@post
}

// ResearchRoutes.kt - Same pattern
val user = call.principal<FirebaseUserPrincipal>()
?: return@post call.respond(HttpStatusCode.Unauthorized)

// DataRoutes.kt - Same pattern
val user = call.firebaseUser()
if (user == null) {
    ...
}
```

**Current State:** `firebaseUser()` helper exists but inconsistent usage

**Recommendation:** Create authentication middleware that injects user

### 4. Error Handling Pattern

**Files:** All route files

**Pattern:** Try-catch with logging and error response

**Example:**
```kotlin
try {
    // Business logic
} catch (e: Exception) {
    call.application.log.error("Operation failed", e)
    call.respond(HttpStatusCode.InternalServerError, 
        mapOf("error" to "An internal error occurred."))
}
```

**Recommendation:** Create `handleErrors` wrapper function

## SIMILAR IMPLEMENTATIONS

- `server/src/main/kotlin/com/example/smarty/server/agent/DeepResearchAgent.kt` (463 lines)
- `server/src/main/kotlin/com/example/smarty/server/agent/AdvancedDeepResearchAgent.kt` (1159 lines)

   - Estimated effort: 2 hours

   - Inject user into call context

## RECOMMENDATIONS

### Refactoring Priority

1. **Create Generic Repository** (High impact, medium effort)
2. **Extract SSE Emitter** (Medium impact, low effort)
3. **Centralize Auth** (Medium impact, medium effort)
4. **Consolidate Prompts** (Low impact, medium effort)

### Acceptable Duplication

1. **Provider Implementations** (Polymorphic design)
2. **Data Model Definitions** (Different ORMs required)
3. **SQL Schema Patterns** (Database conventions)
4. **Service Separation** (DigestService vs DigestScheduler)

### Monitoring

1. Add code duplication detection to CI (e.g., detekt SimilarRule)
2. Set threshold for acceptable duplication
3. Review new code for copy-paste patterns
