# MODULES

## Module Structure

The project uses a multi-module Gradle build with 3 primary modules:

```
Smarty/
├── app/           # Android application module
├── common/        # Shared Kotlin Multiplatform module
└── server/        # Ktor server module
```

---

## APP MODULE

**Path:** `app/`

**Type:** Android Application

**Build File:** `app/build.gradle.kts`

**Namespace:** `com.example.smarty`

**Purpose:** Android thin-client UI application with Jetpack Compose

### Key Components

**MainActivity.kt:**
- Single activity architecture
- Compose UI hosting
- Permission handling
- Intent processing (share, voice note, camera note)
- Shake detector for chat mode toggle
- Speech-to-text integration

**SmartyApplication.kt:**
- Global initialization
- ResourceManager setup
- LazyDecompressor initialization
- WorkManager configuration
- Network monitoring
- Worker scheduling (DailyDigest, CalendarSync, SyncWorker)

**Room Database (`data/local/SmartyDatabase.kt`):**
- Version 38 schema
- Entities: Note, Category, ChatSession, ChatMessage, CalendarEvent, Timer, etc.
- FTS5 full-text search integration
- 38 migration scripts
- Junction tables for note relationships

**Feature Modules:**
- `chat/` - SSE streaming, agent interaction, memory management
- `notes/` - Note CRUD, versioning, categories, stacks
- `calendar/` - Event management, note linking
- `audio/` - Media3 ExoPlayer integration, playlist management
- `auth/` - Firebase authentication, login screen

### Dependencies

**Major Libraries:**
- androidx.core.ktx, lifecycle, activity.compose
- androidx.compose.bom, material3, navigation
- Room (runtime, ktx, paging, compiler via KSP)
- Paging3, Coil, Palette
- OkHttp, Ktor Client
- Firebase (auth, messaging, crashlytics)
- Media3 ExoPlayer
- WorkManager
- DataStore Preferences
- Security Crypto
- ZXing (QR codes)
- Compose Markdown rendering

## COMMON MODULE

**Path:** `common/`

**Type:** Kotlin Multiplatform (JVM + Android)

**Build File:** `common/build.gradle.kts`

**Namespace:** `com.example.smarty.common`

**Purpose:** Shared protocol definitions and data models

### Directory Structure

```
common/src/commonMain/kotlin/com/example/smarty/
├── core/
│   └── domain/
│       └── model/           # Core domain entities
├── data/
│   └── model/               # Data transfer models
├── features/
│   └── chat/
│       └── agent/
│           └── models/      # Agent-related models
└── protocol/
    ├── AgentProtocol.kt     # AgentCommand sealed class
    ├── AgentEvent.kt        # AgentEvent sealed class
    ├── ClientEvents.kt      # ClientEvent sealed class
    ├── HandshakeProtocol.kt # Handshake protocol
    └── SyncModels.kt        # Sync protocol models
```

### Key Components

**AgentProtocol.kt:**
- `AgentCommand` sealed class with 20+ command types
- Commands: AddNote, UpdateNote, DeleteNote, ScheduleEvent, SetTimer, LaunchApp, etc.
- ProtocolWebCitation data class

**AgentEvent.kt:**
- `AgentEvent` sealed class for SSE streaming
- Event types: Processing, ToolCall, Result, Error, Command, StateSync, ToolBlocked
- SearchQueryResult nested class

**ClientEvents.kt:**
- `ClientEvent` sealed class for client→server events
- Events: ToolResult, ActiveNotesResponse, SearchResultsResponse, RecallResultsResponse, etc.

**Domain Models:**
- Note, Category, ChatSession, ChatMessageEntity
- CalendarEvent, SmartyTimer
- Citation, ConnectionUsage
- NoteVersion, AIMemory

### Key Components

**Application.kt:**
- Ktor embedded server setup (Netty, port 7860)
- Plugin installation (CORS, RateLimit, SSE, ContentNegotiation, Auth)
- Database initialization
- Digest scheduler startup
- Route configuration
- Security monitoring setup

**ServerAgent.kt:**
- Main AI agent with tool execution loop
- RAG integration with vector store
- Conversation summarization
- Tool orchestration (search, memory, schedule, device)
- Multi-tenant isolation via userId
- Execution limits (30 min timeout, 100 tool calls, 200 iterations)
- Progressive thinking persistence

**DeepResearchAgent.kt:**
- Research session management
- Clarification question workflow
- Parallel web search execution
- Citation tracking
- Progress file for long-running research
- Timeout handling (12 min warning, 15 min force complete)
- User interruption handling

**AdvancedDeepResearchAgent.kt:**
- ACH (Analysis of Competing Hypotheses) matrix
- Cognitive bias detection
- Source credibility hierarchy (Tier 1-5)
- ALCOA source verification
- BLUF-style intelligence reporting
- Knowledge graph construction
- Entity extraction
- Security checkpoints (OWASP Top 10 for Agentic AI)

**ProviderRouter.kt:**
- Capability-based model selection
- Health tracking (circuit breaker)
- Model mapping:
  - FAST_CHAT → gemini-1.5-flash
  - REASONING → gemini-1.5-pro
  - VISION → gemini-1.5-flash
  - IMAGE_GENERATION → imagen-3.0-generate-001

**DatabaseFactory.kt:**
- HikariCP connection pool (max 10)
- PostgreSQL migration execution
- Exposed ORM initialization
- Environment-based configuration

## Module Dependencies

```
┌─────────────────┐
│      app        │
│  (Android App)  │
└────────┬────────┘
         │ depends on
         ▼
┌─────────────────┐
│     common      │
│  (KMP Module)   │
└─────────────────┘

┌─────────────────┐
│     server      │
│  (Ktor Server)  │
└────────┬────────┘
         │ depends on
         ▼
┌─────────────────┐
│     common      │
│  (KMP Module)   │
└─────────────────┘
```

**Note:** app and server are independent modules that both depend on common. They do not depend on each other.
