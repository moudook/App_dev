## CRITICAL DEBT (Fix Immediately)

### 1. Kotlin Version Mismatch

**Debt:** Kotlin version inconsistency between modules

**Location:** Root build.gradle.kts vs server build.gradle.kts

**Current State:**
```kotlin
// Root: forces 2.1.21
force("org.jetbrains.kotlin:kotlin-stdlib:2.1.21")

// Server plugins: uses 2.1.0
plugins {
    kotlin("jvm") version "2.1.0"
}
```

**Impact:**
- Potential runtime incompatibilities
- Build reproducibility issues
- IDE warnings

**Interest Rate:** High (could cause subtle bugs)

**Principal:** 1-2 hours to fix

**Remediation:**
```kotlin
// Align all versions to 2.1.21
plugins {
    kotlin("jvm") version "2.1.21"
}
```

### 3. Memory Leak in Thinking Cache

**Debt:** Thinking cache not cleared on error

**Location:** ThinkingStorageManager.kt

**Current State:**
```kotlin
fun appendThinking(sessionId: String, thinking: String) {
    thinkingCache
        .computeIfAbsent(sessionId) { StringBuilder() }
        .append(thinking)
}

fun finalizeAndGetThinking(sessionId: String): String {
    val thinking = getCurrentThinking(sessionId)
    thinkingCache.remove(sessionId)  // Only removed on success
    return thinking
}
```

**Impact:**
- Memory growth over time
- Potential OOM under load
- Performance degradation

**Interest Rate:** High (memory leak)

**Principal:** 1 hour to fix

**Remediation:**
```kotlin
fun finalizeAndGetThinking(sessionId: String): String {
    return thinkingCache.remove(sessionId)?.toString() ?: ""
}

// Add cleanup for abandoned sessions
fun cleanupAbandonedSessions(thresholdMs: Long) {
    // Remove sessions older than threshold
}
```

### 4. Session Hijacking Risk

**Debt:** Client can potentially reuse session IDs

**Location:** ChatRoutes.kt

**Current State:**
```kotlin
if (sessionId.isNullOrBlank()) {
    sessionId = chatRepository.createSession(userId, "New Chat")
} else {
    val existingSession = chatRepository.getSession(userId, sessionId)
    if (existingSession == null) {
        val created = chatRepository.createSessionWithId(userId, sessionId, "Continued Chat")
        // Creates session with client-provided ID
    }
}
```

**Impact:**
- Potential session hijacking
- Data leakage between users
- Security vulnerability

**Interest Rate:** Critical (security risk)

**Principal:** 2-4 hours to fix

**Remediation:**
- Reject client-provided session IDs
- Generate server-side UUIDs only
- Validate session ownership before reuse

### 6. No Row-Level Security

**Debt:** Multi-tenant isolation only in application

**Location:** All repository files

**Current State:**
```kotlin
// Application-enforced isolation
select { (Notes.userId eq userId) }
```

**Impact:**
- Bug could expose cross-tenant data
- No defense in depth
- Compliance risk

**Interest Rate:** High (data isolation risk)

**Principal:** 4-8 hours to fix

**Remediation:**
```sql
ALTER TABLE notes ENABLE ROW LEVEL SECURITY;

CREATE POLICY user_isolation ON notes
    USING (user_id = current_setting('app.current_user_id')::uuid);
```

## DEBT PREVENTION

### Process Improvements

1. **Code Review Checklist**
   - [ ] No commented code
   - [ ] No magic numbers
   - [ ] Proper error handling
   - [ ] Tests included

2. **Definition of Done**
   - Tests passing
   - Documentation updated
   - No new detekt warnings
   - Security review for sensitive changes

3. **Technical Debt Tracking**
   - Add debt items to issue tracker
   - Tag with "technical-debt"
   - Review in sprint planning
   - Allocate 20% capacity to debt

### Tool Improvements

1. **Static Analysis**
   - Enable detekt
   - Add custom rules
   - Fail CI on violations

2. **Automated Testing**
   - Minimum coverage threshold
   - Required integration tests
   - Performance regression tests

3. **Monitoring**
   - Memory usage alerts
   - Error rate alerts
   - Performance degradation alerts
